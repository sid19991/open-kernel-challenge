# Data and model indexes

This challenge does not publish sample/eval tensors for download. Kernel correctness uses
fresh random inputs generated by each problem's `reference.py` (`generate_input`) inside
the judge. Serving-track conversations are hidden.

## Hugging Face checkpoints (not downloaded)

| Repo | Role | Approx. size | Access |
|---|---|---|---|
| [meta-models/Muse-Spark-Open-816B-A42B](https://huggingface.co/meta-models/Muse-Spark-Open-816B-A42B) | BF16 weights | ~1.04 TB files / ~1.65 TB footprint | **gated** (manual accept of Muse Model License) |
| [meta-models/Muse-Spark-Open-816B-A42B-NVFP4](https://huggingface.co/meta-models/Muse-Spark-Open-816B-A42B-NVFP4) | NVFP4 weights used by the judge | ~167 GB files / ~537 GB footprint | **gated** |
| [RadixArk/Muse-Spark-Open-DFlash2](https://huggingface.co/RadixArk/Muse-Spark-Open-DFlash2) | DFlash2 draft (serving track) | ~9.1 GB `model.safetensors` | public config/README; weights too large, skipped |

What is stored here:

- `hf/api-*.json` — Hugging Face model/collection API metadata
- `hf/index-*.json` — file path, size, oid for every blob (weights index)
- `hf/tree-*.json` / `tree-recursive-*.json` — directory listings
- `hf/siblings-*.json` — sibling filenames from the model API
- `hf/dflash2/` — public DFlash2 `config.json`, `README.md`, `.gitattributes`
- `hf/DFlash2-config.json` — same config at the hf root for convenience

To download weights after accepting the license:

```
hf download meta-models/Muse-Spark-Open-816B-A42B-NVFP4 --local-dir ./muse-spark-open-nvfp4
hf download RadixArk/Muse-Spark-Open-DFlash2 --local-dir ./muse-spark-open-dflash2
```
