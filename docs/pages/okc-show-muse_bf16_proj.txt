◆ muse_bf16_proj

Dense projections. The attention and MoE-block projections and the router, as
one GPU runs them serving Muse Spark Open on 8×H200. They are BF16 (the router
FP32).

  SGLang      4,830.8 µs  per decode step
  GPU         H200  one, no network
  Limits      10 runs and 20 checks a day

Computation
  # x: [m, k] BF16   W: [n, k] = weights[layer]
  # qkv_gate, o, pooler, unpooler: BF16; router: FP32
  out = x @ W.T  # [m, n], BF16 (router: FP32)

Inputs
  kernel_fn(data: Inputs, state) returns bfloat16 / float32 [m, n]. state is
  what prepare(weights) returned.

  class Inputs(TypedDict):
      x: torch.Tensor  # bfloat16 [m, k]
      config: Config

  class Weights(TypedDict):
      qkv_gate: torch.Tensor  # bfloat16 [2304, 8192]
      o: torch.Tensor         # bfloat16 [8192, 1024]
      pooler: torch.Tensor    # bfloat16 [4096, 8192]
      unpooler: torch.Tensor  # bfloat16 [8192, 4096]
      router: torch.Tensor    # float32 [256, 8192]

  class Config(TypedDict):
      m: int
      # output width; the unpooler's is 1024 up to 8 tokens (this GPU's slice),
      # else 8192
      n: int
      k: int
      # which weight: "qkv_gate", "o", "pooler", "unpooler" or "router"
      layer: str

  Decode loads are SGLang serving with speculative decoding off; verify loads
  are its default recipe, which checks each request's 8-token draft in one step.
